# 다른 PC에서 업데이트·연결하기

1. 실행 중인 이전 서버 창에서 Ctrl+C로 종료합니다. 저장소 폴더에서 `git pull --ff-only`를 실행합니다. 직접 수정한 파일이 있으면 Codex에게 변경 보존 후 업데이트를 요청하세요.
2. Windows는 `start.cmd`, macOS/Linux는 `./start`를 실행합니다. 의존성은 해시가 고정된 파일로 설치합니다. **이번에 출력된 접속 링크**를 엽니다. 기본 포트가 사용 중이면 빈 포트를 자동 선택합니다.
3. PLUG 연결 화면에서 키를 발급받은 **나무 또는 N2를 직접 선택**한 뒤 앱키·앱시크릿을 입력합니다. 새 토큰 발급과 계좌 목록 조회가 성공해야 저장합니다. 실패하면 기존 키가 유지되고 입력란은 비워집니다.
4. 계좌·시장을 선택합니다. 구버전 키 이전 시 기존 계좌가 유일하게 일치하면 선택을 자동 유지합니다. 같은 끝 네 자리 등으로 모호할 때만 다시 선택해야 합니다. 같은 끝 네 자리 계좌는 `계좌 1`, `계좌 2`로 구분하며, 내부에서는 전체 계좌번호의 HMAC을 사용합니다.
5. Codex에게 WORKFLOW.md에 따라 새 잔고를 수집하고 `version: 2`로 리서치를 작성하도록 요청합니다. 이전 연구 파일의 날짜만 바꾸면 안 됩니다. 모든 종목이 검증 완료 또는 출처·사유가 있는 미확인 상태가 되어야 최종 뉴스레터를 만듭니다.

## .env가 있어도 연결되지 않는 경우

이 앱은 **.env를 읽지 않습니다**. 현재 폴더·상위 폴더·사용자 전역 `.env`와 프로세스의 `APP_KEY`, `NHPLUG_*`는 인증 입력으로 사용하지 않습니다. 화면에 “이전 .env 파일 감지 · 이 앱에서는 읽지 않습니다”가 표시되는 것은 정상입니다. SDK의 전역 평문 토큰 캐시도 읽거나 쓰지 않습니다.

이 앱의 이전 `private/plug-credentials.json`만 남아 있으면 `daily.py collect`가 새 토큰과 계좌 목록으로 검증한 후 암호화 이전합니다. 화면의 “이전 저장 키 검증 후 암호화 이전” 버튼이나 `daily.py migrate`로 직접 재검증할 수도 있습니다. 성공하면 해당 평문 파일을 지우고 기존 계좌 선택·저장된 잔고를 유지합니다. 중복된 끝 네 자리로 계좌가 모호하면 자동 선택하지 않습니다. 다른 프로젝트의 `.env`와 전역 SDK 캐시는 삭제하지 않습니다. 이전에 평문 파일이나 공개 로그에 남은 키는 더 이상 사용하는 앱이 없는지 확인한 뒤 PLUG 포털에서 교체하세요.

## 보안 저장소

- macOS: 로그인 키체인의 접근 요청을 허용하고 잠금을 해제합니다.
- Windows: 현재 로그인 사용자의 **자격 증명 관리자**가 사용 가능해야 합니다. 프로젝트 폴더는 현재 사용자 전용 ACL을 적용합니다.
- Linux: 사용자 데스크톱 세션에서 **Secret Service**(예: GNOME Keyring)를 설치·해제해야 합니다. 헤드리스 환경에서 보안 저장소가 없으면 평문으로 대체하지 않고 연결을 중단합니다.

마스터키는 OS 보안 저장소에, 앱키·시크릿·토큰·계좌 식별용 비밀은 인증된 암호문으로 `private/plug-vault.json`에 저장합니다. `installation.json`에는 비밀이 아닌 설치 ID를, 암호화 파일의 metadata에는 브랜드·검증 시각만 담습니다. 다른 PC에는 `private/`를 복사하지 말고 키를 새로 연결하세요. OS 보안 저장소 항목은 `nhplug-investment-report` 서비스 이름으로 찾을 수 있습니다.

## 오류별 조치

| 화면 메시지 | 확인할 항목 |
|---|---|
| 인증 실패 / IGW40031 | 선택 브랜드, 유효한 앱키·시크릿, 발급 상태. 오류만으로 IP 문제라고 단정하지 않습니다. |
| 접근 거절 | API·계좌 권한과 PLUG 등록 조건 |
| 조회 한도 초과 | 잠시 후 재조회. 무조건 토큰을 재발급하지 않습니다. |
| 서버 연결 실패 | 네트워크, 방화벽, PLUG 서버 상태 |
| 보안 저장소를 열지 못함 | OS 사용자·잠금·권한. 다른 PC에서 가져온 암호화 파일 여부 |
| 접속 링크 만료 | start를 다시 실행하고 새 링크 열기. 링크는 10분 동안 한 번 사용할 수 있습니다. |
| 조사 대기 | Codex로 현재 보유 종목을 조사. 잔고 새로고침만으로 기업 분석이 생성되지는 않습니다. |
| 발송 결과 불확실 | 재발송 금지. Gmail에서 같은 날짜·본문·첨부를 대조하고 확인한 메시지 ID로 `verified` 기록 |

## 검증

```sh
# macOS/Linux. Windows에서는 .venv\Scripts\python.exe로 바꿉니다.
.venv/bin/python -m pip install --require-hashes -r requirements-dev.txt
.venv/bin/python scripts/verify.py
npm run build --prefix frontend
```

`unittest discover`는 이 저장소의 pytest 테스트를 수집하지 못할 수 있습니다. `scripts/verify.py`를 사용하며 0개 수집은 실패로 처리합니다. 테스트 임시 폴더는 저장소의 `.test-tmp/` 아래에 만듭니다. 일반 테스트는 가짜 응답과 메모리 보안 저장소를 사용하고 실제 계좌 조회·메일 발송을 하지 않습니다. CI는 Windows/macOS/Linux, Python 3.10/3.14에서 실행합니다. Windows에서는 실제 자격 증명 관리자의 **가상 키** 저장·복호화도 별도 검증합니다.

## 업데이트 후 “키 없음” 알림이 나온 경우

초기 암호화 버전은 구버전 키 파일을 예약 실행에서 이전하지 않아, 키가 남아 있어도 “저장된 API 키가 없습니다”로 표시했습니다. 현재 버전은 같은 설치의 구버전 파일을 자동 검증·이전하고 오류 원인을 구분합니다. 키 교체 때 계좌 선택과 저장된 잔고를 무조건 삭제하던 동작도 제거했습니다.

```sh
.venv/bin/python daily.py doctor
.venv/bin/python daily.py collect
# 명시적으로 이전 키를 다시 검증할 때만:
.venv/bin/python daily.py migrate
```

`doctor`는 키 값을 읽어 출력하거나 외부 인증을 시도하지 않습니다. `legacy_credentials_rejected` / IGW40031은 **키 파일이 없다는 뜻이 아니라 PLUG가 저장된 키의 인증을 거절했다는 뜻**입니다. 이 경우 코드 수정만으로 유효한 키를 만들 수 없으므로 연결 화면에서 발급 브랜드와 유효한 앱키·시크릿을 저장해야 합니다. 같은 거절 키는 정기 실행마다 다시 전송하지 않습니다. 기존에 유효한 암호화 저장이 있으면 구버전 파일로 덮어쓰지 않습니다.

다른 PC에 설치한 키는 이 PC에 자동으로 동기화되지 않습니다. `REPORT_PRIVATE_DIR`을 상대 경로로 지정했을 때는 실행 터미널 위치와 관계없이 저장소 루트를 기준으로 해석하므로 웹과 예약 실행이 같은 데이터 폴더를 사용합니다.
